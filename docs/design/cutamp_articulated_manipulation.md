# cuTAMP 原生关节物体技能：抽屉推拉与柜门开关

日期：2026-09-22  
状态：设计方案，尚未实现或验证成功率。  
适用工作区：`E:\VLA_recovery_workspace\vla-recovery-pipeline`，不是 `vla-recovery-pipeline-bddl`。

## 1. 我们要做什么

在当前项目使用的 cuTAMP 中新增关节物体操作能力：让规划器能搜索“抓把手 → 打开/关闭 → 松手”，并依据关节约束生成可执行轨迹。

采用 TiPToP 所述的扩展方式：**新增谓词、算子、采样器和连续约束，补齐状态传播与轨迹细化。** 不在规划器外另写一套抽屉任务脚本，不更换 cuTAMP，不要求训练策略。

cuTAMP 负责动作序列和连续参数求解；cuRobo 提供可复用的 IK、避碰与运动规划能力；MuJoCo 提供关节结构和仿真执行反馈。受约束的推拉路径需要新增算子自己的细化逻辑，不能假设普通端点规划会自动保持把手接触。

范围分两类：

- **先实现滑动抽屉**：单个 slide 关节、固定柜体、可抓把手，先验证空抽屉的打开和关闭。
- **再扩展转轴柜门**：单个 hinge 关节，复用同一套谓词和算子，替换运动学并验证圆弧运动。

这里“柜子”指柜子的抽屉或柜门，不是搬动整个柜体。第一版不覆盖锁扣、弹簧复杂机构、多关节联动、无把手推压、操作中重抓和任意杂物接触。

**本方案不以 BDDL 迁移为前置条件。** 保留主工作区现有任务入口；目标解析最终提供“操作哪个部件、打开还是关闭”即可。关节轴、行程和运动几何来自 MuJoCo，不新增对 BDDL 几何范围的依赖。以后更换语言目标来源，不应重写底层技能。

## 3. 新增能力的具体设计

### 3.1 统一描述一个关节部件

拟增加 `ArticulatedPart` 描述，服务于抽屉和柜门，至少包含：

| 信息 | 用途 |
| --- | --- |
| `part_id`、`joint_name`、父/子 body | 唯一确定操作部件与驱动关节 |
| `joint_type`：slide / hinge | 选择直线或圆弧运动学 |
| 关节轴、转轴原点、参考构型与坐标系 | 根据关节值正确计算部件位姿 |
| `joint_range`、当前 `s`、速度 | 行程约束与在线状态 |
| 把手相对部件的变换、把手几何 | 抓取采样与接触约束 |
| 部件几何列表、固定柜体几何列表 | 随关节更新碰撞场景 |
| 打开/关闭目标区间及来源 | 定义任务目标，避免自造成功标准 |

从 MuJoCo 读取静态结构与实时状态，通过 body/joint 的真实连接建立对应关系。不要用“名字含有同一单词”来选择第一个关节。没有显式 handle site 时，可以通过已核实的模型几何或资产配置指定把手，不要求所有模型自动识别。

统一使用米、弧度，并声明每个变换的方向、四元数顺序和轴的坐标系。关节位置增大不一定代表打开，必须保存实际开合方向。不同抽屉不能共享未经验证的绝对阈值。

目标区间由任务语义和资产开合定义确定，并与现有任务评测条件核对；MuJoCo 的机械行程本身不定义任务成功。规划日志应记录目标区间来源。不要为了新技能先改掉主工作区现有的任务判定。

### 3.2 谓词与算子

以下是拟定语义名称，实施时适配实际 cuTAMP 的类型与参数约定。

谓词最小集合：

- `Articulated(part)`、`HandleOf(handle, part)`：静态对象关系。
- `Open(part)`、`Closed(part)`：任务层开合状态；两者不是逻辑补集，半开可以两者都不满足。
- `HandleGrasped(part, grasp)`：手正在抓该部件的把手。
- 复用 `HandEmpty` 及机器人当前构型谓词。

连续状态中另存关节位置 `s`，不把任意实数值枚举成大量符号状态。任务搜索只需区分关闭、中间、打开等有限模式；运动计算保留真实数值。实际有限模式与符号搜索参数的接法需依据锁定版本实现，不能直接把伪代码当 API。

| 算子 | 前提 | 效果及连续约束 |
| --- | --- | --- |
| `GraspHandle(part, grasp, q)` | 手空闲；目标有有效把手 | 添加 `HandleGrasped`，删除 `HandEmpty`；约束抓取位姿、可达与接近避碰 |
| `OpenArticulated(part, grasp, ...)` | 已抓把手；部件不在打开目标模式 | 添加 `Open`，移除旧开合模式；关节进入打开目标区间，保持抓取和避碰 |
| `CloseArticulated(part, grasp, ...)` | 已抓把手；部件不在关闭目标模式 | 添加 `Closed`，移除旧开合模式；关节进入关闭目标区间，保持抓取和避碰 |
| `ReleaseHandle(part, grasp, q)` | 已抓把手 | 删除 `HandleGrasped`，添加 `HandEmpty`；不改变部件关节位置 |

Open/Close 共用一个连续实现 `ArticulatedMotion`，区别只是目标区间。若原生搜索仅支持正前提，则用显式互斥模式编译上表中的否定条件。每个算子同步维护机器人构型，抓把手的状态不能与普通物体 `Holding` 同时出现。

动作顺序由搜索产生，例如：

```text
MoveFree → GraspHandle → OpenArticulated → ReleaseHandle → MoveFree
```

将最终 `HandEmpty` 作为本次独立开关技能的收尾要求，避免计划达到 `Open` 后仍抓着把手便结束。以后组合任务可以显式修改收尾要求。

不能直接复用 `Pick` 将抽屉当作自由物体附着到手上：抽屉仍然连接固定柜体。

### 3.3 连续运动学与约束

记 `q` 为机械臂配置、`s` 为部件关节值、`G` 为固定的“把手坐标系到末端坐标系”抓取变换。核心约束为：

```text
T_world_ee(q) = T_world_handle(s) · G
```

滑动抽屉的把手沿关节轴平移；转轴柜门的把手绕转轴旋转，位置和朝向都随角度变化。可统一用关节运动学计算 `T_world_handle(s)`；必须考虑参考构型偏置，不能无条件假设模型零位就是关闭位置。

拟新增约束及对应残差：

| 约束 | 检查内容 |
| --- | --- |
| `ArticulationLimits` | `s` 位于实际机械行程内 |
| `ArticulationTarget` | 终点 `s` 位于目标区间内 |
| `HandlePoseConsistency` | 末端相对把手的位置、旋转误差在容差内 |
| `ArticulatedCollisionFree` | 更新部件位姿后，无非法碰撞，包含机器人与部件/柜体 |
| 复用机械臂运动约束 | 关节限位、自碰撞、相邻配置连续性 |

将约束残差接入 cuTAMP 的代价计算和可行性检查，分别设置位置、角度、关节与碰撞容差。只加入软代价不够：超容差的候选不能被标为可行。

第一版无需完整接触力优化，也无需可微 MuJoCo。读取模型后，用张量运算实现单关节运动学及残差即可。这样解决的是运动学可行性；抓持摩擦与真实执行效果留给仿真验证。

### 3.4 采样器与 rollout

把手采样器提供少量不同抓取方向、位置和夹爪宽度的候选；目标关节值在合规区间内选取，初期可固定一个留有容差余量的目标。不要盲目选择行程极限。

候选必须评估完整行程：能抓到把手，不代表拉到终点时仍可达。某个抓取无解时，返回下一候选，而不是放松抓取一致性约束。

rollout 增加各部件的关节状态和对应几何位姿：

- 抓把手：改变抓持模式，不改变抽屉开合量。
- 打开/关闭：更新 `s`，计算抽屉/柜门、把手的位姿，提供给后续算子与碰撞计算。
- 松手：保持更新后的关节状态。
- 无关部件：维持原状态。

抽屉中的自由物体不自动视为刚性附着物。初期测试用空抽屉；带内容物时重新观测真实状态，不能将任意物体默认跟随抽屉运动。门后空间、抽屉内部放置等组合能力另行验证。

### 3.5 轨迹细化：接入新增算子，不绕过规划器

接近把手、释放后的退出继续使用 cuRobo 自由运动规划。Open/Close 的运动细化分支执行：

1. 在当前 `s` 与目标 `s` 之间生成有序关节路径。
2. 计算每个路径点的把手位姿和目标末端位姿。
3. 用连续 IK/局部细化求机械臂配置，沿用前一点作为初值，并检查配置跳变。
4. 对同步的 `(q, s)` 检查抓取一致性、限位和碰撞；必要时加密路径点。
5. 对最终插值、平滑和时间参数化后的轨迹再次检查；失败则返回 cuTAMP 尝试其他候选。

这是原生算子的轨迹求解逻辑，不是让外部控制器临时猜“该怎么拉”。不能只约束两个端点后调用普通自由规划；不能认为独立逐点 IK 成功就证明中间连续路径可行。

路径细化初期可以离散采样加密，不必一次实现通用连续碰撞证明，但必须记录采样分辨率和最大残差，明确检测精度边界。

### 3.6 碰撞与执行

拆分固定柜体和运动部件的几何，避免一个整体包围盒堵住真实可用空间。随 `s` 更新运动部件；避免同时保留它的初始静态副本造成重复碰撞。

碰撞例外按“几何对 + 接触阶段”声明：允许手指接触把手、允许模型定义的机构接触，不允许手腕撞柜体。不能整体关闭柜体碰撞，也不能将一切初始重叠都忽略。

输出计划除原有轨迹、夹爪指令外，附带部件标识、目标区间、抓取变换、预期关节路径和阶段标签。跨进程 problem/plan 序列化必须往返保留这些数据。

现有 LIBERO 执行器会将关节路径转成末端路径，因此要为关节操作阶段启用完整位姿跟踪并保持夹持；不能沿用仅跟踪 XYZ 的分支。机器人执行结果不能仅依据原始关节轨迹的避碰结果推断。

执行时监测实际关节进度和手—把手误差；发生明显滑脱、停滞或跟踪超差就停止并返回原因，重新观测后再规划。到位后释放并短暂观察是否保持目标状态。不得通过直接设置抽屉 `qpos` 或额外焊接约束来伪造执行成功。离线运动学对照测试可使用独立仿真实例设置状态，不影响正式 episode。

## 4. 具体改哪些代码

### 项目仓库

在第 2 节列出的文件中完成数据读取、目标绑定、原生接入、序列化与执行。关节模型、运动学和诊断宜集中到一个小模块（例如拟新增 `articulation.py`），不要散落成针对 task 名称的判断。

另外检查：

- `scene_graph.py` 的关节关联和开关状态生成：使用明确关节绑定及目标定义。
- `engine_capabilities.py` 与实际启用 skill pack 的能力注册：只有实现通过验证后才开放新 primitive；注册名称本身不创造能力。
- runtime 和 runner 的目标过滤、算子过滤及 fallback：遇到不支持的关节物体应明确返回 unsupported，不能把 `Open` 丢掉后按空目标成功返回。

### 实际使用的 cuTAMP 依赖

以锁定版本为准定位以下扩展点；路径名称对应此前检查的 TiPToP 分支，不保证部署版本完全一致。

| 模块 | 改动 |
| --- | --- |
| `tamp_domain.py` | 新类型、谓词、原生算子及搜索注册 |
| `tamp_world.py` / 环境构建 | 保存关节结构、状态、把手和分部几何 |
| `task_planning/constraints.py` | 新约束的参数结构 |

不要求每个文件都单独新增一套机制；已有通用接口能复用就复用。关键是新算子贯通搜索、优化、细化、执行，而非仅修改文件数量。

## 5. 最短实施顺序与验收

只安排三个阶段，不先建设通用技能平台，不先重跑 mining。

### A. 跑通一个抽屉的原生开关技能

选一个模型明确、无内容物的滑动抽屉。接入上述最小谓词和算子；用少量抓取候选、固定目标区间完成求解与执行。

验收：

- 在几个关节位置对照 MuJoCo，验证把手运动学和碰撞几何变换。
- cuTAMP 搜索输出包含原生抓把手、开关、松手算子，不靠 task 专用脚本补动作。
- 关闭、半开状态可以执行打开；打开、半开状态可以执行关闭；已满足目标时不做无意义推拉。
- 实际关节到位并在松手后保持；记录任务判定，不以轨迹走完代替成功。
- 能识别错误把手绑定、越界目标、不可达抓取，并返回明确失败。

### B. 接入恢复流程并验证泛化

将新能力接到现有 recovery 目标选择和 runner；覆盖不同抽屉层、柜体位姿、机器人初始配置。初期对“手已经占用”明确拒绝该技能，不伪造 `HandEmpty`；需要时由正常任务规划先安排放置动作。

验收：problem 序列化往返不丢信息；目标不被过滤；执行失败会回报并重新观测；原有 pick/place 回归不退化。用固定测试用例和种子分别统计规划成功率、执行成功率、任务成功率、耗时与失败原因，不仅统计总成功率。

### C. 扩展到单转轴柜门

复用算子、状态结构和接入流程，增加 hinge 运动学，验证沿圆弧改变位置与朝向。重点测试开启方向、门板扫掠碰撞、靠近转轴的抓取、末段机械臂可达性。

柜门通过前，不宣称支持所有 articulated objects。带物抽屉、“打开后放入再关闭”、锁扣和中途重抓属于后续独立能力，不作为第一版验收前置条件。

## 6. 困难、可解性与失败边界

| 困难 | 解决方式 | 判断 |
| --- | --- | --- |
| 原生实现对既有算子有硬编码 | 补齐类型分派、参数初始化、rollout 和细化链路 | 可解决，工程工作 |
| 单关节与机器人耦合 | 把手运动学加固定抓取变换，计算一致性残差 | 可解决，不需要可微物理 |
| 端点可行但中间不可行 | 连续配置求解、加密检查、最终轨迹复查 | 核心技术难点，需要实验 |
| 柜体几何过粗、合法接触误判 | 分部几何和阶段化接触例外 | 可解决，调试工作较多 |
| 抓到把手却拉不到底 | 结合完整行程筛选抓取，多候选回退 | 通常可解决；可能真实无解 |
| LIBERO 跟踪、摩擦、滑脱 | 完整位姿跟踪、速度控制、实际状态检查 | 能改善，不能仅凭规划保证 |
| 内容物自由运动、多关节联动 | 需要额外建模与验证 | 不纳入第一版 |

建议统一记录少量故障标签：`invalid_articulation_binding`、`no_feasible_handle_grasp`、`articulation_path_infeasible`、`collision_blocked`、`execution_tracking_failed`、`handle_slip_or_no_progress`、`target_not_reached`。这足以区分语义绑定、规划和执行问题，不需要先建新的诊断系统。

可行性结论：**先实现已知模型的单自由度抽屉，技术路线明确；最大风险在全程受约束轨迹和实际接触执行，不在谓词定义。** 暂不承诺成功率或固定工期，用阶段 A 的实测结果决定后续投入。

## 7. 与现有 mining、BDDL 工作的关系
