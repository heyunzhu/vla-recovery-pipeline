# 按 skill pack 建任务变体的三种改法

日期：2026-10-03

变体从 pack 里某条 skill 对应的源任务复制而来。一次只改一个轴：目标、物体摆放，或 profile 所依赖的几何。源任务原样保留，作为对照。

不改 skill，也不改 profile。语言只在目标变了的时候改写成新目标的那一句，用来和 `(:goal)` 保持一致。不靠同义词或邻句去试正则。

每条变体记两层标签。一层是源 skill 的 `applies_to` 和 `trigger` 在这条任务上该不该成立。另一层按槽位记 profile 还对不对：抬手或转腕、抓取、grounding、geometry、放下步数。抓取仍然对、落点已经不对，分成两格，不给整条链打一个结论。

## 共同步骤

1. 找到源 skill 的源 BDDL，以及评测实际加载的 init states 文件。Runner 复位时用的是 init states 里采好的仿真状态，不是现场从 `(:regions)` 再采样。
2. 复制到单独目录。不写回 LIBERO-Pro 原 suite，不改共享物体资产。
3. 只改下面三节里的一种。
4. 用环境加载这条 BDDL，`reset()` 之后调用 `check_success()`。加载失败，或初始状态已经算成功的，丢掉。这一步只保证任务能跑，不保证策略或 recovery 能完成。
5. 正式链路看进门之后的结果。`force_recovery_query` 看不依赖原来那次触发、只合并 hint 时，各槽位的 profile 还能不能做完。

## 改目标

改的是成功条件，以及 recovery 用来绑定落点的那个 goal。物体、初始摆放、网格都留在源任务上。

BDDL 里一起改这三处：

- `(:goal)`：新的 atom 只用场景里已经有的物体或 region。谓词沿用源任务能表达的关系，例如 `On` 或 `In`。
- `(:language)`：写成这件新事情的那一句，和 `(:goal)` 指同一个物体、同一种关系。
- `(:obj_of_interest)`：换成新的被操作物体和目标。

`(:init)`、`(:regions)`、物体列表和 init states 不动。可以继续用源任务的 init states，因为物体还在原来的位置。

仓库里已有的生成器就是按这个范围改的：`rewrite_bddl` 改语言、兴趣物体和 goal，不重新摆放，也不换网格。按 skill 建变体时同样只动这三处，并且变体必须锚在一条源 skill 上，而不是按模板把一个场景里所有物体对都生成出来。

标签怎么填：静态 `applies_to` 会跟着新语言变，这是目标变了的结果。抓取 profile 看的是物体形状，往往还对。grounding、geometry、place 看的是落到哪一块，往往已经不对。hint 的 `applies_to` 若仍然成立，正式链路里旧的落点 profile 会被合并进来。这就是要记下来的矛盾。

## 改物体摆放

改的是物体初始位置。目标、语言、物体种类和网格不动。`applies_to` 里的句子条件应保持成立。变的是距离、谁离手更近，以及 profile 用到的间隙和碰撞。

只改 `(:regions)` 里的 `(:ranges)` 不会生效。评测复位加载的是 init states 文件里的状态。区域改了、init 文件仍是源任务的那一份，物体还会出现在旧位置。

做法：

1. 改相关物体所在 region 的平面范围。物体仍放在原来的支撑面上，范围不要重叠，也不要移出支撑面。
2. 用改过的 BDDL 重新采样 init states，再保存成这条变体自己的 init 文件。
3. 评测这条变体时指向新的 init 文件，不要指回源任务的 init。

`(:goal)`、`(:language)`、`(:obj_of_interest)` 和物体资产不动。

标签怎么填：句子层面的 `applies_to` 仍应成立。`trigger` 里的末端距离、最近物体、认错是否成立，由新摆放决定，跑之前不凭源任务的 trace 填写。抓取 profile 的局部采样多半还对；落点和碰撞相关的 geometry、place 可能因为间隙变了而不再对。正式链路和 `force_recovery_query` 要分开记：前者看新摆放下进门条件还在不在，后者看做法本身还行不行。

## 改 profile 依赖的几何

改的是 profile 计算时读到的物体尺寸、朝向或支撑形状。目标、语言、物体中心所在的区域不动。不改 `profiles/*.yaml`，那是在改记忆，不是在改任务。

抓取 profile 从仿真里的包围盒和姿态取顶面、半高和朝向。落点几何从场景里的 site 或物体网格取范围。这些数在物体资产和初始姿态里，不在 skill 文件里。

做法：

1. 为变体复制一份物体或夹具资产，只让这条 BDDL 引用它。共享的 LIBERO 资产保持不动，避免源任务和其他 suite 一起变。
2. 在这份副本上改 profile 真正读取的量：包围盒的厚度或长宽、静止时哪一面朝上、容器或 site 的开口范围。物体中心仍落在源 region 里。
3. 朝向改在 region 的 `(:yaw_rotation)` 或初始姿态上，然后按上一节重新采样 init states。只改 BDDL、沿用旧 init 时，仿真里的朝向不会变。
4. 放大或翻面之后若和邻物穿插，先调到能 `reset()` 的程度。摆放中心仍要留在源区域，避免把这一条变成摆放变体。

`(:goal)` 和 `(:language)` 不动，使源 skill 的句子条件仍然对着这条任务。

标签怎么填：`applies_to` 预期仍然成立。每个槽位的「profile 是否仍然正确」是这条变体要测的量。厚度或朝向变了，抓取槽通常先失效；容器开口变了，geometry 和 place 槽先失效。没被这个几何量用到的槽标成仍然正确。

## 三条之间的界限

| 改动 | 动的文件 | 不动的东西 | init states |
| --- | --- | --- | --- |
| 目标 | `(:goal)`、`(:language)`、`(:obj_of_interest)` | 区域、资产、摆放 | 沿用源任务 |
| 摆放 | region 的 `(:ranges)`，以及新采的 init | 目标、语言、资产、朝向和尺寸 | 必须重采 |
| 几何 | 任务私有的资产副本，必要时加重采朝向 | 目标、语言、物体中心所在区域、profile 文件 | 改了朝向或尺寸导致穿插时重采 |

一条变体只占一行。目标的句子和新的落点要一致，这不算第二条改动。摆放变体重采 init，也不算改几何。
