# C3/C4 spatial-task：50-seed 配对复测

## 结论

1000集完整校验通过。C3为380/500（76.0%），C4为374/500（74.8%），C4−C3为−1.2个百分点。按task聚类的bootstrap 95%区间为[-5.2,+3.4]个百分点，跨过0；当前不能确认整体可靠退化，更不能据此证明两条件等价或不存在遗忘。

500对样本中302对都成功、48对都失败、78对C3成功/C4失败、72对C3失败/C4成功。150对（30%）结果翻转但净差只有6对。单次配对翻转不是遗忘标签，也不是重复执行方差估计。

## 设置与完整性

- 历史C3/C4 pack，固定Pi0/OpenPI模型及runtime commit `7128c1ea6280c227e48561e621fe9da8604c5a6d`；不是训练或调skill。
- 10个spatial-task任务，每条件每任务50集，共500配对、1000集。
- episode0–49对应环境seed1–50及预存init_state_idx0–49。C3/C4配对同task/seed/init状态；不是一个固定场景重复50次。
- policy seed90，环境每集播种；不保证规划器和策略全部随机源按episode重播种。续跑在独立进程初始化，仍可能有执行随机性/进程重启影响。
- 自然mining trigger；最多2次recovery，每次最多200steps，最多1次replan。保留query/recovery trace、视频和命令。
- 四lane运行，cuTAMP经独立flock串行。两次中断后按完整样本续跑，保留旧attempt，不计中断样本为机器人失败。
- 2026-10-12原launcher冻结资产校验通过，20jobs各50个完整唯一样本；`all.done`存在，保存索引与重新扫描一致，最终四lane退出码均0，无`.failed`或`.infrastructure_invalid`。
- 这是验证器口径下1000个有效样本、没有基础设施无效标记；不等于全部旧尝试均完整，也不把轨迹跟踪/抓取失败等任务错误当成基础设施错误。

## 调用与首次winner

采用episode的`recovery_calls>0`定义实际发生接管，首次winner来自query trace中首个`hook_fired`且`skill_id`非空的记录。只是首次调用归因，不是完整因果分析或后续调用序列等价证明。

| 项目 | C3 | C4 |
|---|---:|---:|
|发生recovery的episode|474/500（94.8%）|469/500（93.8%）|
|总recovery调用|621|608|
|发生recovery且最终成功|379|374|
|首次触发query中位数|6|6|

78个C3成功/C4失败的配对中：63个首次winner相同；3个两侧均触发但winner不同；11个C4没有触发；1个只有C4触发。72个反向变好的配对中：65个首次winner相同；1个winner不同；6个只有C4触发。

整体接管比例接近，损失样本大多数并非首次winner换了。但相同winner不能证明其参数、调用状态、时间或执行轨迹相同；C4不触发也不自动证明旧规则被改坏，需检查首次触发前状态是否不同。不要把旧5-seed实验的“11个丢失均同winner”套到本轮78个丢失上。

## 不确定性与子集

task作为cluster，以各task的配对成功率差为单位有放回采样10个task、100000次，固定分析随机种子20261012，percentile 95%区间[-5.2,+3.4]个百分点。仅10个task，区间是探索性估计，不代表对所有具身任务的总体推断。次要独立pair假设下exact McNemar p=0.6832，未用于替代cluster分析。

- 本轮seed1–5：50对，C3为37/50（74%），C4为41/50（82%），+8个百分点；丢失3、新增7。
- 本轮seed6–50：450对，C3为343/450（76.22%），C4为333/450（74%），−2.22个百分点；丢失75、新增65。
- 历史5-seed运行的78%→70%不是本轮seed1–5。这是新的尝试，不能合并为同一次运行；小子集方向改变提示结论对样本/执行尝试敏感，但不单独证明变化全由随机性产生。

## 对benchmark的意义

本轮是在同冻结基础模型下对外部pack演化的旧任务保持性复测，不是新工具增长/合并方法的评价，也没有独立的未见任务泛化划分。结果支持：原先8个百分点差距没有在扩大到50seed的总体均值中保持；存在较多双向行为变化，均值接近并不意味着行为不变。当前既不能确认系统性遗忘，也不能排除局部任务差异。

应继续把调用/选择、参数/依赖变化、物理执行分开归因。当前实验没有固定状态同pack重复、append-only冻结共同profile或oracle执行等消融，不能分离这些原因。
