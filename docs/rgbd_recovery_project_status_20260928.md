## 一、我们在做什么

项目要让 VLA 在 LIBERO 任务执行受阻时，调用已有的 recovery 规划和技能链路继续完成任务。现有链路在关键位置直接读取 MuJoCo 的物体位姿、几何、接触及任务成功信号；我们负责把 recovery 做决策所需的场景信息改为由 **RGB-D 观测、任务语言、机器人本体状态与相机标定**产生，并用实验量化代价和效果。MuJoCo 仍负责仿真物理及独立的评测打分。

项目目前有两条互补的推进线：

| 推进线 | 目标 | 截至目前的状态 |
| --- | --- | --- |
| 同学负责的 cuTAMP 与技能扩充 | 扩大规划器可处理的情况，并为原先无法处理的 LIBERO-Pro 任务补 skill，提高 recovery 覆盖率与得分 | 据同学本周反馈，cuTAMP 已扩展几项能力，完成后继续补 LIBERO-Pro skill；“预期超过 Aspire 点数”是目标预测，尚无可引用的实测结论。 |
| 我们负责的 RGB-D 迁移 | 让目标绑定、几何、规划和执行依据视觉场景，而非物体真值；建立可复现的对照评测 | 已实现可回放观测、初步视觉场景和单帧模型基线；还没有视觉 recovery 在线成绩。 |

两条线最后要在同一套场景接口与评测条件下汇合。cuTAMP/skill 扩充解决“能规划和执行哪些恢复动作”，RGB-D 迁移解决“恢复动作根据什么信息做决定”。

## 二、准备怎么做

目标数据流是：

```text
同步 RGB-D + 相机标定 + 机器人本体状态
                ↓
检测/分割 → 可见表面几何 → 实例 ID、区域和不确定性
                ↓
任务语言绑定目标、参照物与关系
                ↓
同一份视觉场景 → runner / cuTAMP planner / executor
                ↓
执行动作 → 新观测 → 视觉抓取与目标验收 / 必要时重规划
```

首先保留现有 oracle recovery 作为**独立对照模式**，逐步新增 visual 模式。visual 模式的目标实例、障碍物、放置区域、抓取状态及任务完成判断必须来自允许的观测；缺失信息要显式标成 `unknown`，不能悄悄退回 MuJoCo 物体状态。任务最终成功率仍可由评测器使用仿真真值计算，但这个信号不能反向进入 recovery 决策。

迁移顺序是先做少量代表任务的纵向闭环，再扩展 skill 和任务覆盖。第一版优先覆盖普通 pick/place、需要同类物体消歧的语言目标，以及一种容器或明确目标区域；抽屉、柜门、开关等关节操作需另做视觉运动估计与验收。

## 四、当前还缺什么

1. **泛化感知。** 首批跨任务结果已暴露误检、漏检和跨类别重叠；需固定通用描述生成规则并在未参与调词的任务上测目标/参照物检出、错误绑定、ID 切换和 `unknown` 比例；扩展句式时记录拒绝与覆盖率。
2. **语言与几何闭合。** 已有单帧空间关系的候选 ID 绑定；还要核验颜色等描述，把“放到哪里”绑定到可见支撑/容器区域，并给 cuTAMP 提供有坐标系、来源和置信范围的几何，而非直接把可见点云当完整物体。
3. **在线入口切换。** runner、cuTAMP perceiver 与 executor 共用一份按时间戳缓存的视觉场景；处理抓牢、掉落、放置成功和目标验收；封住物体真值、site、contact、`done` 以及静默 oracle fallback。
4. **技能包与评测。** 为选定任务迁移独立的 visual skill pack，先做离线 admission，再做相同 task/init/seed 与预算下的在线对照及未参与调参的 held-out 验证。

因此，**现在不能宣称已经完成 RGB-D recovery，也不能报告它的成功率或与 Aspire 的分数差**。同学关于超过 Aspire 的表述同样应保留为待验证预期。

| 顺序 | 交付与验收点 | 与同学工作汇合的接口 |

第一版完成的判据是：观测与场景可重放；三个在线入口共用视觉场景；pick/place、语言实例绑定和至少一种容器/目标区域形成闭环；visual skill pack 独立；视觉决策中真值访问和 oracle fallback 为零；有对照和 held-out 结果。达标后再讨论更广的 LIBERO-Pro 覆盖和关节类任务。
